# DOCX page export

The page export dialog offers Word (DOCX), including optional child pages. Each
page is an ordinary `.docx` inside the downloaded ZIP. Space and full database
archives keep their existing formats; this feature does not import DOCX.

The exporter reuses the shared page preparation, heading-numbering preferences,
page metadata, access-checked synced blocks and permitted database snapshots.
Every tab is expanded and details content is retained. The document uses native
paragraphs, headings, lists, editable tables, hyperlinks, page breaks, block text
direction and Word footnotes. PNG, JPEG and GIF images supplied by authorized
attachment preparation are embedded in the package. Unsupported or unavailable
images retain their alternative text instead of a remote image relationship.

The renderer does not fetch URLs, use HTML `altChunk`, embed macros or execute
content. Ordinary HTTP(S), mail and telephone links remain clickable. Script,
iframe and object content is omitted. Both the container and materialized source
pages are checked again before returning generated bytes. A revoked or deleted
source rejects that export rather than returning the prepared document.

The rendered HTML input is limited to 16 MiB and 100000 elements; nesting is
limited to 64. A document supports at most 100 embedded images, 64 MiB of image
bytes and 40 million pixels per image. Table limits are 10000 rows and 64 columns.
Exceeding a limit fails the page export; no truncated DOCX is returned. The HTML
limit includes data URLs, so it may be reached before the separate image limit.

`docx-renderer.spec.ts` validates OOXML parts and reads the output through
Mammoth. `export-security.spec.ts` covers source revalidation. The database live
acceptance downloads DOCX alongside Markdown, HTML, PDF and Docmost, then checks
native footnotes and content from inactive tabs through a real reader.

For visual acceptance, build the application and run
`node apps/server/test/docx-export-fixture.mjs`. The synthetic output stays under
`artifacts/docx-export`; inspect all pages in Word or LibreOffice. Record the
application/version, rendered page count and any visible defects separately from
automated XML and text checks. Fixture generation alone is not visual acceptance.
