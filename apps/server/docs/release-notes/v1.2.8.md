# Docmost v1.2.8 release notes

`v1.2.8` is a production-search and responsive-interface reliability release.
It supersedes `v1.2.7`.

## Production Typesense hardening

- Production deployments that use `SEARCH_DRIVER=typesense` must include the
  checked-in `compose.typesense.yml` overlay in every Compose lifecycle command.
- The overlay pins Typesense 30.2 by digest, keeps port `8108` private, mounts
  the API key from `TYPESENSE_SECRET_FILE`, and preserves the external
  `TYPESENSE_VOLUME_NAME` data volume.
- Typesense now runs with a read-only root filesystem, all capabilities
  dropped, `no-new-privileges`, rotated logs, and explicit limits of 512 MiB,
  one CPU, 256 processes, and an eight-thread worker pool.
- The application and collaboration services wait for a healthy Typesense
  service and read the same file-backed key. Operators must render and validate
  the complete production, Typesense, and host-specific overlay set before
  entering maintenance.

## Responsive interface and accessibility

- The client declares a light-only browser color scheme so forced-dark mobile
  browser modes do not invert the otherwise light application theme.
- Page and database header actions use consistent responsive menus, accessible
  names, focus behavior, and touch targets. Favorite actions and compact page
  preferences retain their state and remain usable in narrow layouts.
- Full-screen context drawers, the share dialog, table-of-contents actions, and
  related mobile acceptance coverage now follow the same responsive contract.

## Editor tables and maintenance

- Table column allocation again preserves intrinsic content width and exposes
  horizontal overflow when a table cannot fit its container, while compact
  tables continue to consume the available width.
- Column resize and drag-and-drop behavior use deterministic layout fixtures so
  browser acceptance covers both fitted and overflowing tables.
- The workspace pins `browserslist` 4.28.7 to keep the client build dependency
  graph deterministic, and editor browser readiness checks are less sensitive
  to transient initial loading states.

## Upgrade, acceptance, and rollback

- There are no new database migrations, public API or TypeScript contract
  changes, or deployment environment keys between `v1.2.7` and `v1.2.8`.
- Operators must still use the coordinated backup, restore rehearsal,
  production preflight, migration, acceptance, and rollback workflow. Existing
  Typesense data is retained in the external volume; do not run a full reindex
  unless post-deployment search checks show projection drift.
- Before acceptance, verify sign-in, page editing, attachments, collaboration,
  Draw.io, page/attachment/Dictionary search, narrow header actions, light-theme
  behavior, table overflow, service health, and the expected image provenance.
- Rollback before acceptance uses the previous immutable `v1.2.7` application
  image and database volume. Retain the previous image, volume, and coordinated
  backups for at least 14 days after acceptance.

The Docker release workflow accepts only tag `v1.2.8` for manifests whose
version is `1.2.8`. Deploy only the registry digest whose OCI
`org.opencontainers.image.version` is `1.2.8` and whose OCI revision equals the
tagged commit.
