# Docmost v1.2.6 release notes

`v1.2.6` is an editor and knowledge-access release for stable large tables,
reliable column reordering, synced-block selection, and an optional done-only
AI/RAG policy. It supersedes `v1.2.5`.

## Editor tables and synced blocks

- Ordinary ProseMirror tables now use a local fixed layout backed by a
  `colgroup`. Short input keeps the current geometry; content that no longer
  fits redistributes available width without growing the table, and deleting
  that content restores the equal baseline.
- Column drag handles move the complete logical column across every row,
  including merged column ranges. The table menu also exposes boundary-aware
  move-left and move-right commands. Drag handles remain hidden in read-only
  mode and at mobile widths.
- Collapsed table borders are excluded from the column budget, removing the
  one-pixel horizontal scrollbar that previously appeared without real
  overflow. Structurally wide tables still retain horizontal scrolling.
- Synced-block references preserve ordinary text selection instead of
  intercepting the initial pointer gesture.

## Done-only AI and RAG access

- Space administrators can optionally restrict AI retrieval, external RAG
  export, and built-in RAG synchronization to ordinary pages whose current
  status is `DONE`. The policy is disabled by default and composes with the
  existing explicit page exclusions.
- When enabled, pages without a status or with any other status are omitted;
  changing a page into or out of `DONE` is reflected by incremental export and
  synchronization. Attachment projection follows the filtered parent page.
- The administrator guide, public RAG contract, Postman examples, shared API
  contracts, and all supported locales describe the same policy.

## Migration, verification, and rollback

This release adds `rag_search_done_only` to `ai_space_content_policies` with a
default of `false` and creates `idx_pages_active_space_status` for active-page
status filtering. Run the normal coordinated backup, disposable restore
rehearsal, production preflight and plan, then apply migrations through the
documented `production:db migrate --yes` workflow. Account for the index build
in the capacity and maintenance plan before accepting the deployment.

Before `accept`, verify sign-in, collaboration, large-table editing and column
reordering, AI retrieval, RAG export/synchronization in both policy states, and
the expected Docker image provenance. Rollback before `accept` uses the
documented `production:db rollback --yes` path and the previous immutable image
digest. The migration rollback drops the status index and the new policy
column, so any configured done-only value is lost.

The Docker release workflow accepts only tag `v1.2.6` for manifests whose
version is `1.2.6`. Deploy only the registry digest whose OCI
`org.opencontainers.image.version` is `1.2.6` and whose OCI revision equals the
tagged commit.
