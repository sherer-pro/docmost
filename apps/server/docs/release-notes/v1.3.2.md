# Docmost v1.3.2 release notes

`v1.3.2` repairs complete MCP document reads, adds explicitly authorized readers
for metadata, comments, saved versions, database cells and attachments, and
includes the unpublished page-history viewport and PWA runtime-configuration
recovery fixes. It also includes the previously published main-branch tooling
and synced-block ID compatibility updates since the `v1.3.1` tag.

## Complete MCP reads

- Full serialized results remain bounded at 32 KiB. Large pages, outlines,
  nodes, tables, database contexts, trees and child lists expose continuations.
  Text chunks preserve Unicode. Content cursors bind to the tool, resource and
  version; discard collected chunks and restart after `MCP_SOURCE_CHANGED`.
- Outline `#index` references work directly in nested tables. Large cells have
  explicit truncation markers and full-node references. An oversized database
  row is represented before the row cursor can advance.
- Safe metadata includes document type/database ID, readable parent, dates,
  authors/editors/contributors, labels, lock state and enabled document fields.
  Current page access and AI exclusions remain authoritative.

Six additional MCP-only tools require explicit capabilities:

| Tool | Capability |
| --- | --- |
| `getPageMetadata` | `page.metadata.read` |
| `getDatabaseCellContent` | `database.cell_content.read` |
| `getComment` | `page.comment.read` |
| `getPageVersion` | `page.history.content.read` |
| `getAttachmentText` | `page.attachments.text.read` |
| `getAttachmentFileChunk` | `page.attachments.file.read` |

Existing comment/history/template/publication readers retain their independent
capabilities. New permissions are never granted by a migration. Configure the
deployment, workspace, space and selected-key intersection deliberately.

Attachment text reads use existing PDF/DOCX/TXT/MD extraction and report explicit
processing/unsupported states; reads never start processing. Original files are
returned as Base64 fragments containing at most 16 KiB of bytes. Local storage
checks open-file identity before/after reading; S3 uses conditional versioned
ranges. No storage paths, credentials, signed links or private chat files are
exposed. MCP authorization remains restricted to `/mcp`.

Credentials, capabilities and the actor's current role are revalidated before
publication. Errors retain `isError=true` and add safe machine-readable codes.
The administrator guide contract is v45 across all twelve locales.

## Upgrade and verification

The root, client and server manifest versions are `1.3.2`; the only matching
release tag is `v1.3.2`. Publish from that exact tag and select the resulting
`shererpro/docmost:1.3.2` immutable registry digest, with matching OCI revision.
Do not deploy a mutable `latest` reference.

This release introduces no database migration beyond the current migration
ledger. Follow every intervening release note, the production deployment and
backup runbooks, create/verify an off-host coordinated backup, rehearse against
an isolated current production copy, and retain the source image/volumes.

The implementation passed the complete isolated Node 22 release suite and a
real HTTP/PostgreSQL/Redis/storage MCP matrix. Production acceptance must also
repeat the original failed pages and outline/table references, enumerate the
full tree, reconstruct large text/JSON and attachment bytes, verify document
metadata/comments/history and check cross-space/capability denial. Evaluate
response content and `isError`, rather than HTTP status alone.

Keep ingress closed through the documented migration acceptance and service,
collaboration, attachment and database-health checks. Accept only after the
required observation window. Revoke the six new capabilities before an
application downgrade. After admitting writes, do not automatically restore an
old database volume; use the documented forward recovery procedure.
