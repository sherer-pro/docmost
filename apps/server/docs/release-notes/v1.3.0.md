# Docmost v1.3.0 release notes

`v1.3.0` adds structured knowledge projection v2, optional hybrid retrieval,
and contextual follow-up query rewriting. It includes the AI and RAG Sync
reliability fixes since `v1.2.9`.

## AI retrieval and knowledge contracts

- Open WebUI retrieval supports `vector` and `hybrid_with_vector_fallback`.
  Existing spaces retain vector mode. Optional `followUpRewriteEnabled`
  rewrites only the retrieval query using safe user history and currently
  readable citation titles. Invalid output, timeout, or provider failure falls
  back to the original query without blocking generation.
- AI run responses expose the effective retrieval query, rewrite outcome,
  safe error code, latency, and token counts to the conversation owner.
- RAG scope schema v4 advertises `projectionVersion: 2`, content-policy version,
  and enabled processor capabilities. Structured pages, database rows, and
  dictionary terms use `structured-knowledge-v2`; `.md` and `.txt` attachments
  use `attachment-text-v1`. PDF, DOCX, image, and audio processors remain
  disabled. External RAG clients must refresh scope and restart synchronization
  when the changed scope invalidates their previous cursor.
- RAG Sync preserves dictionary ownership with `pageId: null`, completes early
  reconciliation even after its last pending upload is removed, and preserves
  unowned writer-test files. Existing signed metadata remains readable; writes
  remain v2 by default. Projection changes can trigger automatic reconciliation
  of files owned by the binding.
- AI file inputs remain mounted during asynchronous uploads. Agent recovery
  hashes match the current document, and block operations reject discarded text.

## Migration and configuration

Migration `20260903T010000-ai-rag-hybrid-rewrite` adds retrieval mode and rewrite
settings to `ai_space_configs`, and retrieval audit fields to `ai_runs`.
Existing configurations default to `vector` and rewriting disabled. Its `down`
operation removes those settings and audit fields, losing rewrite history;
normal rollback uses the preserved pre-upgrade database volume instead.

Production Compose now forwards these controls to API and collaboration:

```dotenv
RAG_SYNC_METADATA_WRITE_VERSION=2
RAG_CONTENT_PROCESSORS_ENABLED=attachment-text-v1
```

Preserve existing provider credentials, allowlists, and per-space settings.
Do not enable hybrid retrieval, rewriting, metadata v3, or reserved processors
as an incidental part of upgrading. The administrator guide is version 22 in
all 12 locales; both fork overviews and their source checks describe v2.

## Upgrade, acceptance, and rollback

Deploy only the verified `shererpro/docmost:1.3.0` registry digest whose OCI
version is `1.3.0` and whose OCI revision equals the `v1.3.0` tag commit.
Include production, canonical Typesense, and all required host overlays.
Preserve existing Typesense data, pinned infrastructure images, and limits.

Create and verify a coordinated PostgreSQL/file-storage backup and an off-host
copy. Rehearse restoration, upgrade, and rollback in an isolated environment
with real mail and external synchronization disabled. Use `production:db`
`preflight`, `plan`, and `migrate --yes`; keep ingress closed during acceptance.

Verify sign-in, page save/reload, attachments, two-session collaboration,
Draw.io, and page/attachment/dictionary search. Verify AI retrieval and Agent
write operations, and RAG Sync convergence without duplicated dictionary files
or changes to foreign files. Observe service health, restarts, OOM, critical
errors, and database collation warnings for 30 minutes before acceptance.

On failure before admitting public writes, use `production:db rollback --yes`
with the recorded previous image and database volume. After successful
acceptance, run `production:db accept --yes` and retain the previous image,
volume, and backups for at least 14 days. Automatic volume rollback after
acceptance is forbidden because it would discard newly admitted writes.
