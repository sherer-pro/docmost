# Docmost v1.2.9 release notes

`v1.2.9` is an operational reliability release that supersedes `v1.2.8`.

## PostgreSQL migration volume names

- The production database operator now bounds generated candidate volume names
  to Docker's 128-character resource-name limit. Existing short names retain
  the previous `<source>-candidate-<migration-id>` format.
- When a chained source volume would exceed the limit, the operator preserves a
  readable source prefix and adds a deterministic 16-character SHA-256
  fingerprint before the migration suffix. Repeated migrations therefore stay
  within the limit without collapsing distinct source-volume provenance.
- Rollback metadata still records the complete source volume name. Database
  contents, migration ordering, retention rules, and the 14-day rollback
  boundary are unchanged.

This fixes the fail-fast production blocker discovered while deploying
`v1.2.8`: the existing source volume name was 127 characters and the generated
candidate name would have been 155 characters. The failure occurred before the
maintenance hook, writer shutdown, backup, or database changes.

## Upgrade and rollback

There are no new database migrations, public APIs, TypeScript contracts, or
environment variables in this release. `v1.2.9` includes the hardened private
Typesense Compose contract and the UI/editor/browser fixes documented in the
[`v1.2.8` notes](./v1.2.8.md).

Use the normal coordinated backup, verified off-host copy, disposable restore
rehearsal, `production:db preflight`, `plan`, `migrate --yes`, acceptance, and
`accept --yes` sequence. Before acceptance, verify the bounded candidate volume
name, the recorded complete previous-volume provenance, all service health,
the immutable application digest and OCI revision, and the existing Typesense
volume and limits. Rollback before acceptance continues to use
`production:db rollback --yes` and the recorded previous application digest and
PostgreSQL volume.

The Docker release workflow accepts only tag `v1.2.9` for manifests whose
version is `1.2.9`. Deploy only the registry digest whose OCI
`org.opencontainers.image.version` is `1.2.9` and whose OCI revision equals the
tagged commit.
