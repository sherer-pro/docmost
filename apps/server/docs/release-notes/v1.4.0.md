# Docmost v1.4.0

Inbound MCP supports page creation, title changes, targeted Markdown edits,
image uploads, replies and thread resolution. Write tools are available to
authorized MCP API keys through the existing `/mcp` endpoint, with revision
checks, exact previews and retrievable operation receipts.

## Upgrade

Follow the [production deployment guide](../../../../docs/DEPLOYMENT.md).
Keep ingress closed until verification succeeds. Apply
`20261118T000000-mcp-write-operations.ts` with the full migration set. Deploy
the collaboration service before the API and pin both to the same release
image. Preserve the existing extension flag and the workspace and space
policies. Allow space for 2 MiB decoded images plus Base64 and JSON overhead
on `/mcp` if the deployment proxy uses a smaller request cap.

The migration adds six write capabilities and two comment read capabilities
to API keys that already exist with `key_type=mcp`. Check that custom workspace
and space policy restrictions remain effective. New keys select reads by
default, with writes available individually. Check read-only OAuth and RAG
auth compatibility separately.

Use synthetic pages in an isolated space to verify a migrated key, a newly
created read-only key and a restricted target. Check exact preview, stale
rejection, repeated commit and status, page and file IDs, reply uniqueness,
thread state, live content hashes and the persisted inline anchor. Verify the
page and attachment changes independently of the MCP response, then remove the
fixtures and revoke the temporary credentials.

## Rollback

Remove the write capabilities, enable read-only policy or disable
`AI_BUILTIN_TOOL_EXTENSIONS_ENABLED` to stop optional tools while keeping
receipts and data. After accepting traffic, retain the live database and use
forward recovery. The schema rollback discards the write receipts and queued
MCP mutation dispatches, restores the saved capability list on unedited keys
and removes write capabilities from later lists. Existing content is retained.
The previous live volumes are only a rollback candidate before accepting
writes.
